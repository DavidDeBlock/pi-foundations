## Issue Enrichment Workflow

When invoked to enrich a GitHub issue (typically after rejection by `issue-readiness` or `prd-auditor`), follow this process.

### 0. Read Previous Handoffs
Fetch all comments and scan for `🤖 Agent Handoff:` prefix.
Parse JSON blocks to understand what gaps previous agents identified — these are your search targets.

```bash
gh issue view <number> --json title,body,labels,comments
```

### 1. Identify Knowledge Need
- What information is required?
- Which files/directories are relevant?
- Are there any specific patterns or conventions to find?

### 2. Search Strategically
- Use PATH REFERENCE first (core system files)
- Check existing documentation
- Search codebase with grep/find/scripts/

### 3. Retrieve and Summarize
- Load only relevant sections
- Summarize large inputs
- Extract key insights

### 4. Enrich Issue Body (Archivist Only)
You are the **only** agent permitted to edit issue bodies. Follow these rules:

1. Check if `<!-- AGENT-FINDINGS-END -->` marker exists in the body
2. If found, insert new findings **before** it (append within section)
3. If not found, append both markers and content at end of body:

```markdown
<!-- AGENT-FINDINGS-START -->
## Agent Findings

### Archivist — YYYY-MM-DD
- Finding 1 based on codebase exploration
- Finding 2 with file references (e.g., `server/src/routes/auth.ts`)
<!-- AGENT-FINDINGS-END -->
```

4. **Never** edit content outside these markers
5. Run the following command to apply the body update:

```bash
gh issue edit <number> --body "<new body>"
```

### 5. Post Structured Comment
After enriching the body, post a structured comment on the issue following [.pi/ISSUE-INTERACTION.md](../../.pi/ISSUE-INTERACTION.md) §2:

```bash
gh issue comment <number> --body "$(cat <<'EOF'
## 🤖 Agent Handoff: `archivist`

> *This was generated by AI during issue enrichment.*

### Summary
[One-line summary of what was enriched]

### Findings / Advice
- [Finding 1 added to body]
- [Finding 2 added to body]

---
<details><summary>Structured Data</summary>

```json
{
  "agent": "archivist",
  "flow": "issue-enrichment",
  "verdict": "enriched",
  "labels": {
    "add": ["ready-for-agent"],
    "remove": ["needs-info"]
  },
  "findings": [
    {"topic": "<gap addressed>", "source": "<file or doc referenced>"}
  ]
}
```

</details>
EOF
)"
```

### 6. Apply Label Changes
Signal readiness for re-review:

```bash
gh issue edit <number> --add-label "ready-for-agent" --remove-label "needs-info"
```

### 🔍 Codebase Discovery Tools

When searching the codebase, **prefer structured project scripts over raw CLI commands** (`find`, `grep`, `cat`). These scripts are AST-aware, faster (~1s), and produce deterministic output that fits within token limits.

| Task | Run This Instead Of |
|------|---------------------|
| Map folder structure | `tsx scripts/tree/code-tree.ts <path> --depth 2 --max-files 60` |
| List API routes & methods | `tsx scripts/synthesize/api-surface.ts server/src/routes` |
| See file exports/types | `tsx scripts/extract/exports.ts <file>` |
| Understand domain entities | `tsx scripts/synthesize/domain-model.ts [dir]` |
| Check test coverage | `tsx scripts/validate/test-coverage.ts [dir]` |

**Rule:** Before using raw CLI for discovery, check if a matching script exists in `scripts/`. Use `--json` flag when output needs to be parsed programmatically.

### 🔍 Maestro Analysis Toolkit (Python)
For Python projects (like Maestro), use these scripts instead of raw CLI. They parse ASTs and produce structured Markdown tables or JSON.

| Task | Run This Instead Of |
|------|---------------------|
| See file exports/classes/functions | `python3 .pi/maestro/scripts/exports.py <path>` |
| Map import dependencies (stdlib/third-party/local) | `python3 .pi/maestro/scripts/imports.py [dir]` |
| Analyze class inheritance trees | `python3 .pi/maestro/scripts/class-hierarchy.py [path]` |
| Inspect pipeline scripts (setup/run/context vars) | `python3 .pi/maestro/scripts/pipeline-inspect.py <path>` |
| Parse flow JSON configs (phases/transitions) | `python3 .pi/maestro/scripts/flow-info.py <name>` |

**Rule:** Use `--json` flag for machine-readable output. Use `--help` for specific usage details.
