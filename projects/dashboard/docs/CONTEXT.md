# Dashboard — Context

> ⚠️ **Stub.** To be filled in once the design grilling is complete and ADRs are written.

## One-line summary

Personal dashboard that mirrors and organizes your Chrome bookmarks, browsing history, and YouTube subscriptions — running on a home server, fed by a Chrome extension.

## User

- Solo user (David)
- 2 × Windows machines (personal + shop), both with Chrome signed into the same account
- 1 × in-house Ubuntu server on the same LAN hosting the dashboard
- Chrome Sync keeps both machines' bookmarks/history aligned, so the dashboard deals with one logical Chrome profile

## What the dashboard does (high level)

- **View + organize Chrome bookmarks** — folders + tags, same model for bookmarks and YouTube videos
- **View Chrome history** — full-history bulk import at install, extension pushes new visits in real time
- **Ingest YouTube subscriptions** — Data API `subscriptions.list`, refreshed periodically (v3.0)
- **Detect new videos from subscriptions** — RSS polling per channel, dropped into the same folders/tags model (v3.0)
- **News & Weather glance page** — `/news-weather` with Belgian news + Ghent 7-day forecast on top, news by category below (v5.0)
- ~~Save YouTube videos~~ — deferred to v3.1 (ADR-003)
- ~~Mirror YouTube saves to a YouTube playlist~~ — deferred to v3.1 (ADR-005)
- ~~View YouTube history via Takeout~~ — deferred to v3.1 (ADR-003)

## What's locked in

| Decision | Value | Notes |
|----------|-------|-------|
| Deployment | Self-hosted on Ubuntu server, LAN-accessible | `http://ubuntu-server:<port>` |
| Chrome data ingestion | Extension + one-time bulk import from `History` SQLite | Extension handles ongoing; bulk import gets the long tail |
| Chrome sync direction | Two-way, dashboard wins | Edits in dashboard push to Chrome; Chrome-only edits sync back |
| YouTube data ingestion (v3.0) | Data API for subscriptions + RSS polling for new videos | ADR-009; saves + watch history deferred to v3.1 |
| Categorization | Folders + tags, unified for bookmarks and YouTube videos | Chrome folders map 1:1; tags are dashboard-only |
| YouTube categorization | Dashboard DB is source of truth; YouTube playlist is a mirror | v3.0 has no mirror (subscriptions are read-only); ADR-005 applies once v3.1 ships saves |
| Subscription filter UX | Hybrid: import all subs, dashboard toggle per channel (default included); separate `is_important` flag for future LLM job | Music channels get toggled off in UI |
| Transcript fetching | Implemented in v3.x | On-demand per video or automatic per subscription; stored as timed local segments |
| LLM summarization | Implemented in v3.x as on-demand YouTube Insight Cards | MiniMax through a provider-neutral OpenAI-compatible client; automatic summaries and morning briefing remain follow-ups |
| App auth | Single password (HTTP Basic) | Password bcrypt-hashed on the server |
| Extension auth | Shared secret API token | Generated by dashboard, pasted into extension config |
| MVP scope | v1 = read-only Chrome bookmarks + categorize + search | Write-back, history, YouTube = later slices |
| News & Weather (v5.0) | Belgian news + Ghent weather on a single `/news-weather` page | PRD-008 + ADR-010; parallel ingestion pipeline (RSS/Atom/JSON API), per-source due-check, failure isolation via `Promise.allSettled`, DB-backed source registry seeded by migration `025_news.sql` |
